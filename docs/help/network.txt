# Networking
rozOS talks TCP/IP through an Intel e1000/e1000e network card (QEMU)
or a Realtek RTL8111/8168 gigabit card (most real PC boards, phase 22).

== The layers ==
  card driver   kernel/drivers/net/e1000.c, rtl8168.c - send and receive
                frames
  lwIP          a small TCP/IP stack inside the kernel: ARP, IPv4,
                ICMP (ping), UDP, TCP, DHCP, DNS
                (since phase 25a: 256 KiB TCP window with window scaling -
                fast downloads from far servers like GitHub)
  sockets       kernel/net/socket.c - turns lwIP into file descriptors
  rozlibc       socket(), connect(), send() ... ([[sockets]])
  TLS           BearSSL in userland ([[tls]], [[rozhttp]])
  programs      [[ifconfig]], [[ping]], [[nslookup]], [[http-get]], [[rozpkg]]
A kernel thread "netd" checks the card every millisecond and runs
lwIP's timers (see it with `kmon` then `ps`).

== Addresses ==
At boot DHCP asks for an address. In QEMU's user-mode network:
  10.0.2.15   rozOS               10.0.2.2   your PC (and gateway)
  10.0.2.3    DNS server          127.0.0.1  rozOS itself (loopback)
The DNS server is written to /etc/resolv.conf; fixed names are in
/etc/hosts ("host" = 10.0.2.2). See [[qemu]] for the host side.

== Try ==
  `ifconfig`                 address and counters
  `ping -c 3 10.0.2.2`       is the PC answering?
  `ping google.com`          name lookup + internet
  `http-get http://example.com/`   fetch a web page
  `http-get -h https://example.com/`   the same over TLS
  `rozpkg update`            the package list ([[rozpkg]])
There is no firewall and no IPv6 yet.

== Real PC (Realtek) ==
On a real PC plug in the cable before booting; the router gives the
address by DHCP and the taskbar's network icon loses its red slash.
Wi-Fi and 2.5G cards (RTL8125) are not supported yet.
If there is no network, run `kmon` then `nic`: it shows the chip (XID),
its registers, the link (PHYstatus, BMCR/BMSR) and the driver's init
log. If no driver is active it lists the PCI network devices instead.
Take a photo of that screen - it shows where the card stopped.
No address from the router? `ifconfig` tells where DHCP is (looking for
a server, requesting, waiting to retry). `kmon` then `netlog dhcp`
(phase 22e) shows what happened since boot (DHCP started, link up/down,
address set by hand, address received) and the last 16 DHCP frames,
kept apart so that a busy network cannot push them out. Setting an
address by hand turns DHCP off on purpose (`ifconfig eth0 dhcp` turns
it on again); if DHCP is found off without that, it starts again by
itself. `kmon` then `netlog` (phase 22d)
lists the last 32 frames - ARP, IP, ports and the DHCP message type
(DISCOVER, OFFER, REQUEST, ACK) - and counts DHCP replies that were
dropped (other MAC, old transaction id, bad options). A photo of it
shows whether the router's OFFER arrives.
