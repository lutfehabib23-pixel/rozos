# Processes
Every program runs as a process in ring 3 (user mode) with its own
address space, open files and current directory. The kernel switches
between ready processes every 10 ms (round robin), so a busy loop
cannot freeze the system.

== Life of a process ==
  fork()     copies the running process (child gets 0, parent the pid)
  execve()   replaces the program in a process with a new one
  exit(n)    ends it; n is the exit code
  wait()     the parent collects the child's exit code
The shell does exactly this for every command ([[rozsh]]).

== When a program crashes ==
A bad memory access, invalid instruction or division by zero ends only
that process, with a signal number:
  4 SIGILL   8 SIGFPE   9 SIGKILL (kill)   11 SIGSEGV (bad memory)
The shell then shows e.g. "segmentation fault (signal 11)" and $? is
128+signal. Try `crash` ([[demos]]).

== Looking at processes ==
`kmon` then `ps` lists them; `kill <pid>` ends one ([[kmon]]).
Memory: code is loaded at 0x400000, the heap grows after it (brk),
mmap areas start at 0x700000000000, the stack is at the top and grows
by itself up to 8 MiB. See [[syscalls]].
