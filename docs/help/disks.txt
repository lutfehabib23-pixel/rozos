# Disks and file systems
rozOS joins several file systems into one tree (the VFS):

  /       ext2 on the disk's root partition (/dev/sda2) - kept
  /boot   FAT32 boot partition (/dev/sda1): kernels ([[partitions]])
  /tmp    tmpfs - in RAM, fast, lost at reboot
  /dev    devfs - devices as files

Phase 24c: every other disk is mounted by itself at boot -
  /mnt/<name>   each known partition of the SATA and NVMe disks
                (for example /mnt/nvmea3 = Windows C:), and
  /mnt/usb      the first file system of a pen drive or USB disk
File systems: ext2, FAT12/16/32, exFAT (read and write) and NTFS (read
only - Windows disks and drives like WD My Passport; compressed and
encrypted NTFS files cannot be read yet). Disks of another OS on a real
computer are read-only; Settings > Disks has an "Allow writing" /
"Make read-only" switch for each disk (C: rozos_diskwrite). Files shows
the mounted disks under "Disks" on the left by their volume label and
kind (phase 24d: "My Passport (USB)", "NVMe", "SATA"); Settings > Disks
and `mount` show the same, and "rozOS pen drive - your files" for the
persistent storage. `kmon` then `usbstat` shows how fast a USB disk is
(commands, average and longest time, timeouts) - `usbstat reset` clears. Boot option
`noautomount` turns the boot-time mounting off. The ISO pen drive keeps
your files: [[persistence]].

Without a disk, / is a tmpfs filled from the initrd (a tar file the
bootloader loads), so rozOS still boots, but nothing is kept. The ISO's
initrd is the whole system; the disk's boot partition keeps only a small
rescue initrd (phase 19h, about 5 MB) for when ext2 cannot be used:
[[rescue]].

== Devices in /dev ==
  console  screen + keyboard (+ serial)    null   discards writes
  zero     endless zero bytes               kbd    raw key codes
  serial0  the serial port                  sda    the whole disk
  sda1 sda2 sda3  the partitions ([[partitions]])
  nvmea nvmea1 ... NVMe SSDs (phase 15a) - mount them with [[mount]]
  sdb sdb1 ...     USB pen drives (phase 15b) - mounted on /mnt/usb ([[usb]])

== Protection on a real computer (phase 15b) ==
On a real PC (not QEMU), disks inside the computer that have no rozOS
partition - your Windows SSD, for example - are READ-ONLY: rozOS can
look but never write. The boot messages say so. Pen drives and rozOS's
own disk are writable. To allow writing anyway, add the word `diskwrite`
to the kernel command line in the boot menu ([[boot-menu]]: press e).

== Driver stack ==
PCI scan -> AHCI (SATA), NVMe and USB (xHCI) drivers -> block layer with a 16 MiB
cache (4 KiB pieces) -> partitions (GPT/MBR) -> ext2 and [[fat]] -> VFS.
Writing (phase 25b): small writes (folders, file details, small files) wait
in the cache for about 2 seconds, then go to the disk together, sorted and
joined into big commands - many times fewer commands, much faster on pen
drives. Big files go straight to the disk. `sync` (or [[kmon]]'s `sync`)
writes everything now; umount, reboot and poweroff do it by themselves.
On the PC `make disk-check` runs e2fsck and fsck.fat. kmon's `disks` shows
every file system in detail.
