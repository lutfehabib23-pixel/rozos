# Redirection and command lists
Every program starts with three open files: 0 = input (stdin),
1 = output (stdout), 2 = errors (stderr). Normally all three are the
console. Redirection connects them to files instead:

  `cmd < file`      read input from file
  `cmd > file`      write output to file (the file is emptied first)
  `cmd >> file`     append output to the end of file
  `cmd 2> file`     write error messages to file
  `cmd 2>&1`        send errors where output goes
  `> file`          just create (or empty) file

Several can be combined:  `wc < /etc/motd > /tmp/count.txt 2>&1`

== Several commands on one line ==
  `mkdir /tmp/a ; cd /tmp/a ; pwd`
The commands run one after another, whatever the result.
  `make && kinstall`        the second only if the first worked (exit 0)
  `cd /x || echo no /x`     the second only if the first failed
`true` and `false` are built in, for tests like that.

== Pipes ==
  `ls /bin | wc -l`                  count the programs
  `cat /src/hello.c | wc -w`         the output of one is the input of the next
  `cat big.txt | cat | wc -c > n.txt`   up to 16 commands, redirections too
Every command of a pipe runs at the same time as its own process; data
flows through a kernel pipe (64 KiB) - see [[pipes]].

== How it works ==
The shell opens the file, then uses dup2() to put it on fd 0, 1 or 2 in
the child process before exec(). See [[processes]] and [[syscalls]].
For a pipe the shell first makes a pipe() and gives its two ends to the
two children as fd 1 and fd 0.
